MJC AI Campus Agent
명지전문대학생을 위한 신뢰 가능한 AI 캠퍼스 비서

팀명: 코드한입조
전자공학과 임채호 · AI게임소프트웨어학과 조영남
GitHub: https://github.com/hoo419/mjc-ai-hackathon-codeonebite-team

[요약]
MJC AI Campus Agent는 명지전문대학생이 과목, 시간표, 강의실, 상담 정보를 찾기 위해 여러 시스템과 웹페이지를 오가는 불편을 줄이는 통합 캠퍼스 비서다. 자연어 질문을 이해하는 AI와 검증 가능한 학교 데이터를 분리하여, 편리함과 신뢰성을 동시에 확보했다. 2026학년도 2학기 실제 개설강좌를 수집·구조화해 246개 고유 분반과 516개 수업 세션을 제공하고, Next.js와 FastAPI 기반의 6개 사용자 화면 및 14개 서비스 엔드포인트를 구현했다. 학생 개인 상태는 시연용 데이터로 제한하고 저장소는 JSON과 PostgreSQL 사이에서 교체할 수 있게 설계했다.

[1. 문제 정의]
대학생이 하루에 확인해야 하는 정보는 한곳에 모여 있지 않다. 개설강좌와 신청 현황은 수강신청 시스템에, 시간표는 개인 메모나 별도 화면에, 강의실 위치와 공지는 학교 홈페이지에, 상담 정보는 다시 다른 서비스에 존재한다. 학생은 같은 과목명과 학과 조건을 반복해서 입력하고 결과를 비교해야 한다. 특히 신입생은 축약된 강의실 코드와 학사 용어에 익숙하지 않아 단순 정보 확인에도 높은 탐색 비용을 부담한다.

기존 생성형 AI만으로 이 문제를 해결하면 또 다른 위험이 생긴다. LLM은 자연스러운 문장을 만들 수 있지만 현재 정원, 실제 수업 시간, 신청 가능 상태처럼 바뀌는 학교 사실을 정확히 보장하지 못한다. 따라서 본 프로젝트는 AI가 모든 답을 만들어내는 방식이 아니라, 검증 가능한 데이터 조회 결과를 AI가 이해하기 쉽게 설명하는 방식을 채택했다.

[2. 해결 방안]
학생은 하나의 서비스에서 대시보드, AI 채팅, 과목 검색, 시간표, 강의실, 상담 기능을 이용한다. “지금 신청 가능한 온라인 교양 알려줘”처럼 자연어로 질문하면 서비스가 의도를 분류하고 필요한 조건을 추출한 뒤 Course·Student·Schedule 서비스에서 사실을 조회한다. AI는 조회 결과를 요약하고 과목 카드나 다음 행동을 함께 제시한다.

핵심 사용자 흐름은 검색에서 끝나지 않는다. 학생은 과목 상세에서 교수, 학점, 수업 시간, 강의실, 대상 학과를 확인하고 자신의 시간표에 미리 반영한다. 동일 시간대 과목은 코드에서 충돌 여부를 계산하며, 강의실 축약 코드는 강의실 안내 화면과 연결된다. 상담 화면은 실제 상담 결과가 없는 경우 내용을 꾸며내지 않고 빈 상태와 실제 문의 경로를 안내한다.

[3. 핵심 기능]
대시보드는 학생의 학과·학년·학기 정보와 다음 수업, 공지 바로가기, 주요 기능을 한눈에 제시한다. 과목 검색은 과목명, 상태, 수업 방식, 이수 구분 조건으로 246개 분반을 탐색한다. AI 채팅은 과목 추천, 시간표 질문, 학교 정보 질문을 구조화된 카드와 행동 버튼으로 응답한다.

시간표는 학생이 실제 학교 수강신청 시스템에서 신청을 마친 과목을 개인 일정에 기록하거나 미리보기로 조합하는 기능이다. 실제 학교 수강신청을 대신 실행하지 않는다는 범위를 화면과 API에서 명확히 구분한다. 강의실 화면은 축약 코드, 건물, 층, 호실을 연결하고, 상담 화면은 확인 가능한 정보가 없을 때 정직한 빈 상태와 상담지원팀 연결 정보를 제공한다.

[4. 실제 데이터 수집과 구조화]
강좌 데이터는 2026학년도 2학기 수강편람의 응답을 강좌 구분, 대상 학년, 학과 조합으로 조회해 수집했다. 조회 과정에서는 같은 분반이 여러 학과·학년 조건에서 반복 노출될 수 있다. 본 프로젝트는 동일 과목코드·분반·학기의 반복 노출을 하나의 고유 분반으로 통합하되 정보를 삭제하지 않도록 구조화했다.

한 분반이 여러 요일이나 시간에 수업하면 모든 시간을 sessions 배열에 저장한다. 여러 학과에 개방된 분반은 eligibleDepts 배열에 대상 학과를 함께 보존한다. 이 과정을 거쳐 246개 고유 분반, 516개 실제 수업 세션, 복수 학과에 개방된 21개 분반을 확보했다. 서로 다른 분반은 별도 ID로 유지되므로 같은 과목명이라도 수업 시간과 담당 교수가 다르면 독립적으로 조회된다. “원격시험 배정시간” 문구처럼 실제 수업이 아닌 항목만 세션에서 제외했다.

[5. 시스템 구조]
Frontend는 Next.js 16 App Router, TypeScript, Tailwind CSS와 shadcn/ui로 구성했다. 공용 API 클라이언트가 NEXT_PUBLIC_API_BASE_URL을 사용해 FastAPI와 통신하므로 비밀키가 브라우저 코드에 포함되지 않는다.

Backend는 FastAPI와 Pydantic을 기반으로 API, Service, Repository를 분리했다. Route는 요청과 응답 계약을 담당하고, Service는 검색·시간 충돌·상태 변경과 같은 비즈니스 규칙을 처리한다. Repository는 데이터 접근을 담당한다. DATABASE_URL이 설정되면 PostgreSQL을 사용하고, 설정되지 않으면 JSON과 메모리 저장소로 동작한다. 상위 계층은 저장 방식이 달라져도 변경할 필요가 없다.

구현 범위는 Course 2개, Student 4개, Enrollment 2개, Chat 1개, Counseling 3개, Campus 2개로 총 14개 서비스 엔드포인트이며 별도로 GET /health를 제공한다. 사용자 화면은 대시보드, 채팅, 과목 검색, 시간표, 강의실, 상담의 6개다.

[6. AI 신뢰성 설계]
이 서비스에서 LLM은 학교 데이터의 Source of Truth가 아니다. AI는 자연어 의도 이해, 검색 조건 추출, 도구 선택, 결과 요약과 친절한 설명을 담당한다. 강좌 상태, 정원, 신청인원, 수업 시간, 강의실, 시간 충돌과 같은 사실은 코드·API·DB 결과만 사용한다.

시간 충돌은 같은 요일에서 새 수업 시작 시각이 기존 수업 종료보다 빠르고 새 수업 종료 시각이 기존 수업 시작보다 늦은지를 Python 규칙으로 검사한다. AI가 계산 결과를 임의로 바꿀 수 없다. 검색 결과가 없거나 AI 공급자를 사용할 수 없을 때는 학교 사실을 만들어내지 않고 규칙 기반 응답 또는 확인 불가 안내를 반환한다. 비밀키는 환경변수로 관리하고 Frontend에 노출하지 않는다.

[7. 구현과 검증]
Frontend와 Backend는 API_CONTRACT.md를 공통 계약으로 사용한다. 공통 오류 형식과 Enum, 요청·응답 구조를 문서화하여 두 개발자가 병렬로 구현해도 화면과 API를 예측 가능하게 연결할 수 있도록 했다.

저장소에는 Backend 기능을 검증하는 105개의 테스트 함수가 존재한다. Course 스키마와 검색, 학생 정보, 시간표, 등록·취소, 채팅, 상담, 강의실, 데이터 변환, DB Repository, RAG 검색 모듈과 통합 흐름을 기능별로 분리해 검증하도록 구성했다. 보고서 제작 시점에 Frontend ESLint를 경고 0개 조건으로 재실행해 통과했다. 현재 문서 제작 환경에는 pytest가 없어 Backend 테스트 전체를 다시 실행하지 못했으므로 통과 개수를 주장하지 않고 테스트 구성만 근거로 제시한다.

[8. 차별성과 기대효과]
첫째, 실제 학교 강좌 데이터를 사용한다. 단순 예제 과목 몇 개가 아니라 246개 분반과 516개 수업 세션을 검색할 수 있다. 둘째, AI의 역할을 제한한다. 대화 경험은 AI가 제공하지만 권위 있는 사실은 코드와 데이터가 결정한다. 셋째, 시연용 상태와 실제 데이터를 명확히 분리한다. 강좌는 실제 학기 데이터이고 학생 1명과 초기 수강내역 2건만 시연 흐름을 위한 상태다.

학생은 정보 탐색 시간을 줄이고 자신의 조건에 맞는 과목을 빠르게 비교할 수 있다. 대학은 반복적인 안내 질문을 구조화하고 공식 정보 경로로 학생을 연결할 수 있다. 향후 학교 인증과 공식 API가 제공되면 현재의 Service·Repository 경계를 유지하면서 실제 운영 시스템으로 확장할 수 있다.

[9. 한계와 발전 방향]
현재 서비스는 학교 통합 인증과 연결되지 않아 시연용 학생 상태를 사용한다. 실제 수강신청 행위를 대신하지 않으며, 실제 신청을 마친 과목을 개인 시간표에 기록하거나 신청 전에 조합을 검토하는 도구다. 상담 요청도 실제 담당자 배정 시스템과 자동 연동되지 않는다.

학교정보 검색을 위한 기본 검색 모듈은 구현되어 있지만 pgvector 기반 문서 저장·검색을 포함한 완전한 RAG 고도화는 향후 범위다. 다음 단계에서는 공식 인증 연동, 최신 데이터 자동 갱신, 학교 공지 출처 표시 강화, 상담 시스템 연계, 사용성 평가를 진행할 계획이다.

[10. 결론]
MJC AI Campus Agent는 생성형 AI를 학교 사실의 생성자가 아니라 학생과 검증된 데이터 사이의 인터페이스로 사용한다. 실제 강좌 데이터, 교체 가능한 Backend 구조, 명시적인 안전 규칙을 결합해 5분 안에 작동 흐름을 보여줄 수 있는 수직 통합 MVP를 완성했다. 이 프로젝트의 핵심 가치는 더 많은 기능을 나열하는 것이 아니라, 학생이 필요한 정보를 더 적은 탐색으로 정확하게 이해하고 다음 행동까지 이어가도록 만드는 데 있다.
