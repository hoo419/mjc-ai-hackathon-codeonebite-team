# 해커톤 보고서·발표자료 설계

## 목적

2026학년도 RISE사업단 AI 해커톤 경진대회에 제출할 PDF 보고서와 전체 5분 이내 발표·시연 자료를 제작한다. 교수 2명, 기업 대표 1명, AI 모델 1개의 혼합 심사를 고려해 교육적 가치, 기술적 타당성, 실제 활용성, 구현 근거를 함께 제시한다.

## 제출 정보

- 프로젝트명: MJC AI Campus Agent
- 팀명: 코드한입조
- 팀원: 전자공학과 임채호, AI게임소프트웨어학과 조영남
- 공개 저장소: https://github.com/hoo419/mjc-ai-hackathon-codeonebite-team
- 주제 적합성: 명지전문대학 학생의 학업과 대학생활을 지원하는 AI 캠퍼스 비서

## 핵심 메시지

학생이 여러 학교 시스템과 웹페이지를 찾아다니지 않고도 과목 검색, 시간표 관리, 강의실 확인, 상담 연결을 하나의 서비스에서 처리하도록 돕는다. 서비스는 실제 2026학년도 2학기 강좌 데이터를 사용하며, 사용자 개인 상태만 시연용 데이터로 구성한다. 저장소 계층은 JSON과 PostgreSQL을 교체할 수 있고, LLM은 학교의 권위 있는 사실을 추측하지 않으며 코드·API·DB 결과를 설명하는 역할만 맡는다.

## 데이터 표현 원칙

“981건에서 중복을 제거했다”는 표현은 사용하지 않는다. 학과·학년별 조회에서 반복 노출된 동일 과목코드·분반·학기 강좌를 하나의 분반으로 통합하되, 복수 수업 시간은 세션 배열로 보존하고 여러 학과의 수강 가능 정보는 학과 목록으로 병합했다고 설명한다. 결과는 246개 고유 분반과 516개 실제 수업 세션이다.

## 보고서 설계

10~12쪽 분량의 PDF로 제작한다.

1. 표지: 프로젝트·팀 정보·공개 GitHub 주소
2. 요약: 문제, 해결책, 구현 결과, 기대효과
3. 문제 정의: 분산된 학사 정보와 학생의 탐색 비용
4. 제안 서비스: 통합 AI 캠퍼스 비서와 핵심 사용자 흐름
5. 핵심 기능: 대시보드, AI 채팅, 과목 검색, 시간표, 강의실, 상담
6. 데이터 수집·정제: 실제 강좌 246개와 세션 보존 방식
7. 시스템 구조: Next.js, FastAPI, 서비스·저장소 계층, JSON/PostgreSQL
8. AI 신뢰성: LLM과 권위 데이터의 역할 분리, 실패 시 안전한 응답
9. 구현·검증 결과: 14개 서비스 엔드포인트와 상태 확인 엔드포인트, 6개 화면, 테스트 구성, 정적 검사 결과
10. 차별성·기대효과: 학생, 대학, 확장성 관점
11. 한계와 발전 방향: 인증, 실제 학교 시스템 연동, RAG 고도화
12. 결론

## 발표·시연 설계

발표자료는 3장으로 제한하고 실제 서비스 화면을 중심으로 진행한다. 목표 시간은 4분 30초이며 30초의 여유를 둔다.

- 0:00~0:30: 문제와 서비스 한 문장 소개
- 0:30~3:40: 대시보드 → 실제 강좌 검색 → AI 질문 → 시간표 미리보기 → 강의실·상담 연결 시연
- 3:40~4:15: 실제 데이터, 교체 가능한 저장소, AI 추측 방지 구조 설명
- 4:15~4:30: 학생 가치와 확장 가능성으로 마무리

슬라이드는 표지, 핵심 가치·기능, 기술 신뢰성·성과의 세 장으로 구성한다. 화면 설명용 문장은 짧게 유지하고 내부 제작 메모는 슬라이드에 노출하지 않는다.

## 시각 방향

명지전문대학과 AI 서비스를 연상시키는 네이비·블루 기반의 간결한 스타일을 사용한다. 과도한 카드형 UI와 장식은 피하고 실제 서비스 화면, 큰 제목, 핵심 수치 중심으로 구성한다. 보고서와 발표자료의 색상·용어·수치는 일치시킨다.

## 품질 기준

- PDF의 모든 페이지를 렌더링하여 잘림, 겹침, 한글 글꼴 오류를 검사한다.
- PPTX의 모든 슬라이드를 렌더링하고 오버플로와 겹침을 검사한다.
- 보고서와 발표자료의 수치와 구현 범위가 저장소 근거와 일치해야 한다.
- 실제 수강신청 실행, 학교 인증, 완료되지 않은 RAG 기능을 구현 완료로 과장하지 않는다.
- AI 심사가 쉽게 추출할 수 있도록 기능, 기술, 데이터, 한계, 성과를 명시적인 제목으로 구분한다.
